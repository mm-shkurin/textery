# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [SemVer](https://semver.org/lang/ru/).

Пока API не объявлен стабильным, минорная версия меняется на каждый закрытый
срез (story), патч — на исправления и внутренние изменения. Версия живёт в
`pyproject.toml` и должна совпадать с верхним заголовком этого файла.

## [Unreleased]

## [0.2.0] — 2026-08-20

### Added

- Тест-кейсы стали исполнимыми: у каждого кейса есть идентификатор, описание,
  предусловия, тестовые данные, шаги, точный ожидаемый результат и статус.
  Раньше это были id, заголовок и Gherkin — по ним можно было понять замысел, но
  не выполнить проверку, не задав вопрос автору.

### Changed

- Эндпоинты провайдеров, таймауты, TTL токена и путь к доверенному CA переехали
  из констант модулей в `gigachat_defaults.toml` / `oauth_endpoints.toml`, у
  каждого ключа — переменная окружения, которая его перекрывает.
- Allow-list санитайзера (теги, атрибуты, схемы URL, выравнивания) стал данными
  в `sanitization_policy.toml`. Каждый раз, когда редактор получал новый контрол,
  а список — нет, пользователь молча терял форматирование при перезагрузке.
- Размерные лимиты продукта собраны в `domain/src/shared/limits.toml` вместе с
  обоснованием каждого числа.
- Один маршрутный справочник `router/api_routes.py` вместо десяти литералов
  `/api/v1/...` по роутерам и middleware.
- `ALLOWED_STATUSES` переименован в `DOCUMENT_STATUSES` / `GENERATION_STATUSES`:
  это пространство значений поля, а не список, который правит деплой.

### Fixed

- Контейнер больше не работает под root, а Postgres не публикуется наружу.
- `.env.example` не содержал `POSTGRES_PASSWORD`, из-за чего документированный
  `docker compose up --build` падал на свежем клоне.
- CI монорепозитория не запускал ни один из пяти гейтов и срабатывал только на
  `main`/`dev` — тип ветки, на которой никто не работает.
- Два DTO типизированы `object` вместо `Any`: та же защита от эха пароля в 422,
  но mypy снова проверяет использование.


### Added

- Профиль аккаунта: `GET /api/v1/auth/me` и `PATCH /api/v1/auth/me`
  (переименование). Ответ никогда не несёт байты аватара — колонка `bytea`
  читается только маршрутом самого аватара, иначе каждый опрос профиля тянул бы
  через сеть картинку, которую никто не просил.
- Аватар: `PUT` / `GET` / `DELETE /api/v1/auth/me/avatar`. Тип определяется по
  магическим байтам, а не по заголовку загрузчика, и перепроверяется по
  allow-list при отдаче; есть пред-гейт по `Content-Length` до буферизации,
  пороги на размер стороны (в том числе отказ на `0x0`) и `nosniff`. Отдаётся с
  `ETag` по моменту обновления и `private, no-cache`.
- Удаление аккаунта: `POST /api/v1/auth/me/deletion`, 204. Единственная
  необратимая операция продукта: одна транзакция, дети удаляются раньше
  родителя, ветку подтверждения (пароль или собственный e-mail) выбирает
  сохранённый аккаунт, а не тело запроса. Пустой пароль отвергается до bcrypt.

### Fixed

- `NoStoreMiddleware` сравнивал путь строкой `/api/v1/auth/me`, поэтому все
  ошибки маршрутов под ним (404 от `GET` аватара, 400 на неверном подтверждении
  удаления, 500) уходили вообще без `Cache-Control`: их рисуют обработчики
  исключений, а те выбрасывают всё, что выставил обработчик маршрута. Теперь
  правило — семейство профиля по границе сегмента, и это **умолчание**, а не
  перезапись: маршрут, объявивший свою директиву, её сохраняет.
- Джоб `types` был красным на `HEAD`: у `DeleteAccount._confirmed` были
  аннотированы все параметры, кроме `account`, и `mypy --disallow-incomplete-defs`
  падал с `no-untyped-def`.
- `README.md` описывал API до story-13 (не было ни профиля, ни аватара, ни
  удаления, ни `POST /generations/{id}/retry`, ни `POST
  /documents/from-generation`, ни `GET /projects`) и обещал `/docs` вместе с
  приложением, хотя документация уже была за флагом `API_DOCS_ENABLED`.

- Четыре фикстуры (`account_to_domain_roundtrip`, `resend_concurrency`,
  `reset_failed_attempts`, `verification_code_concurrency`) были определены в
  `statement_fixtures`, но отсутствовали в списке ре-экспорта `conftest.py` —
  pytest падал на setup'е с «fixture not found». Список вёлся руками в двух
  местах; теперь он **вычисляется** (`fixture_exports.fixture_names`) по типу
  обёртки, в которую pytest заворачивает фикстуру, и падает на импорте, если
  найдено меньше ожидаемого — реестр, который молча опустел, даёт ровно тот же
  симптом. Без Postgres вся сюита скипается, поэтому дыру видел только CI.
- CI гонял db-сюиту против `textery` — базы самого приложения. Гард
  `resolve_test_database_url` (добавлен после того, как полный прогон `pytest`
  по живому стенду 2026-08-06 стёр локальные данные) отказывается работать с
  базой, в имени которой нет `test`, и все 68 тестов адаптера падали с
  `RuntimeError`. Оба пайплайна теперь создают отдельную `textery_test`,
  указывают на неё `TEST_DATABASE_URL` и **отдельно прогоняют на ней миграции**:
  шаг `alembic upgrade head` мигрирует ту базу, что названа в `DATABASE_URL`,
  то есть тестовая до сих пор не мигрировалась бы вовсе.
- `test_document_storage_cas_shape` и `test_document_storage_concurrency`
  подставляли `TEST_DATABASE_URL` вручную, литералом с именем `textery`. Эти
  два теста строят собственный engine и зовут `truncate_all` — то есть были
  единственной оставшейся дорогой к тому самому стиранию. Теперь оба идут через
  общий `resolve_test_database_url()`.

### Added

- Гейт на лимит в 200 строк (`scripts/check_file_size.py`, шаг `Check file
  sizes` в джобе `lint`). Лимит объявлен в `.claude/rules/coding-rules.md` как
  жёсткий и был единственным правилом репозитория без проверки в CI — и накопил
  восемь нарушений, включая один production-модуль. Список файлов берётся у
  git, а не обходом файловой системы, чтобы ответ не зависел от того, есть ли
  на машине `.venv` или случайный файл в дереве.
- `requirements-dev.txt` — инструментарий разработки и CI, отделённый от
  runtime-зависимостей.

- Конфигурация логирования (`application/src/app/logging_config.py`, вызывается
  из `main.py` до создания `app`). Двенадцать модулей брали
  `logging.getLogger(__name__)` и писали аккуратные записи, но настроить, куда
  они идут, было некому: корневой логгер оставался на `WARNING` без обработчика.
  Всё, что уровнем ниже, **отбрасывалось** — включая обе строки в
  `exception_handlers.py`, фиксирующие отказ 404 и 409, — а `warning` и выше шли
  через `logging.lastResort`, у которого формат равен голому сообщению: у
  трассировки из обработчика 500 не было ни времени, ни уровня, ни имени
  логгера. Запуск под uvicorn это не лечит: uvicorn настраивает только свои
  собственные логгеры. Уровень читается из `LOG_LEVEL`, по умолчанию `INFO`;
  нераспознанное значение не роняет старт — опечатка в ручке наблюдаемости не
  должна становиться простоем.
- Эндпоинт `GET /health` (порт `HealthProbe` в usecase, `DatabaseHealthProbe` в
  адаптере `db`, `CheckHealth` как usecase). Пробник контейнера в
  `infra/docker/backend.Dockerfile` запрашивал `/openapi.json` — схему, которую
  FastAPI отдаёт из памяти: она возвращает 200 при недоступной БД, поэтому
  экземпляр, потерявший пул, выглядел здоровым и не перезапускался. Новый
  эндпоинт делает round-trip до Postgres и отвечает `503`, а не `200` с телом об
  ошибке: пробник читает код, а не тело. Проверяется только БД — сбой GigaChat
  деградирует один эндпоинт, и объявлять из-за него весь экземпляр нездоровым
  значило бы гасить контейнеры, которые ещё обслуживают вход и редактор.

- Статическая проверка типов: `mypy` над всем production-кодом и всеми
  тестовыми деревьями (261 файл), отдельным джобом `types` в CI. Ранее
  аннотации были во всех сигнатурах, но их никто не проверял. Исключений нет;
  из проверки выведены только шесть `conftest.py` — при раздельных корнях слоёв
  все они являются модулем `conftest` и коллизия имён останавливает проверку.
- Блокирующий джоб `audit` в CI: `pip-audit` по `requirements.txt`. Версии
  запинены точно — это и делает сборку воспроизводимой, и позволяет известной
  уязвимости лежать в файле, пока никто не смотрит.
- Порог покрытия в CI (`--cov-fail-under=90`). До этого `coverage.xml`
  выгружался артефактом и ни на что не влиял.
- Юнит-тесты на `GetDocument`, `ListDocuments`, `GetGeneration`,
  `ListGenerations` — раньше их гоняли только через router-тесты, где сам
  usecase подменён стабом.

### Changed

- `requirements.txt` разделён на runtime и dev. Файл был один, а
  `infra/docker/backend.Dockerfile` ставит именно его, поэтому в
  production-образ уезжали pytest, pytest-cov, pytest-mock, ruff, mypy и пакет
  стабов: лишний вес, лишняя поверхность атаки и `pip-audit`, который не мог
  ответить «уязвимо ли то, что мы деплоим», потому что заодно проверял линтер.
  Джоб `audit` намеренно остался на runtime-файле; джобы `types` и `test`
  ставят dev-файл, который подтягивает runtime сам.
- Восемь файлов, превышавших лимит в 200 строк, разбиты по швам, которые в них
  уже были: три правила-валидатора из `Generation` выделены в
  `generation_validation`, CAS-тесты хранилища разделены на «как выполняется
  update» и «какие строки выбирает sweep», `conftest` db-набора отделён от
  реестра фикстур, две пары Statements разделены на arrange- и assert-половины.
  Число тестов не изменилось.
- README описывает установку dev-зависимостей и то, как поднять `textery_test`,
  чтобы ~70 тестов `adapters/db` перестали молча пропускаться на свежем
  checkout.

- `RegistrationResult.verification_code` больше не `Optional`: `RegisterUser`
  такого состояния не порождает, а тип заставлял DTO читать поле у значения,
  которое по типу могло быть `None`.
- Composition root: 13 фабрик с одинаковым блоком «открыть сессию — отдать
  usecase — закрыть в `finally`» свёрнуты на `request_scoped`.
- README и `.env.example` догнали код. Не описаны были: `YANDEX_CLIENT_ID` и
  `YANDEX_CLIENT_SECRET` — обе проверяются на импорте, то есть **без них
  приложение не стартует**, при том что таблица переменных объявляла
  обязательными только `DATABASE_URL` и `JWT_SECRET`; свежий клон, следующий
  документированной инструкции запуска, подняться не мог. Вместе с ними — шесть
  необязательных `OAUTH_*`, пять эндпоинтов (`/auth/resend-code`,
  `/documents/{id}/export` и три шага OAuth) и два целых модуля
  (`adapters/oauth_provider`, `adapters/rendering`) в таблице архитектуры.
- Разбор ответов GigaChat вынесен в `provider/gigachat_responses.py`: файл
  провайдера перешёл жёсткий лимит в 200 строк после добавления пула и
  таймаутов. Шов не произвольный — обе функции отвечают на один вопрос «что на
  самом деле лежит в этом теле» и не касаются `self`, почему и были
  `@staticmethod` с самого начала.
- Шаг CI `Check production signatures are fully annotated`: `mypy
  --disallow-incomplete-defs` по одним только `src`-корням. Частично
  аннотированная сигнатура проходила настройки по умолчанию — `def
  _validate_state(self, state, provider_name, now) -> None` считается
  типизированной из-за стрелки возврата, поэтому тело проверялось, но с каждым
  параметром как неявный `Any`, который расходится дальше и глушит ошибки
  внутри. Таких функций в production было семь, три — в OAuth-колбэке, где
  неверный тип является вопросом безопасности; все семь аннотированы. Флаг не
  выставлен в `pyproject.toml`, и это не недосмотр: overrides у mypy срабатывают
  по именам модулей, а при раздельных корнях слоёв `usecase/src/auth/...` и
  `usecase/tests/auth/...` — оба `auth.*`, так что ни один шаблон не выбирает
  один без другого (частичные шаблоны mypy отвергает явным сообщением). Пути их
  различают, и CI — единственное место, где путь можно задать.
- `GigaChatProvider` держит один HTTP-клиент на процесс вместо клиента на
  запрос. Раньше каждый вызов входил в `async with httpx.AsyncClient(...)` и
  выбрасывал пул соединений следом, так что каждая генерация платила новый
  TCP-коннект и полный TLS-хендшейк; а поскольку `verify=` — это путь, httpx на
  каждой конструкции собирал SSL-контекст и читал с диска вшитый PEM. Кеш токена
  добавляли ради экономии одного round-trip на генерацию — она уходила обратно в
  рукопожатие. Клиент создаётся лениво (при импорте, где провайдер строится,
  цикла событий ещё нет) и закрывается в `lifespan`; `aclose` добавлен в порт
  `GenerationProvider`, чтобы точка выключения не выясняла `hasattr`, какой
  реализацией её снабдили.
- Таймауты провайдера разведены и названы. Скаляр `timeout=30` задавал httpx все
  четыре фазы одним числом, включая read. Для `/chat/completions`, который
  сочиняет документ на несколько страниц, это правдоподобный источник ложных
  отказов: три попытки по 30 секунд, и строка уходит в `failed` при исправно
  отвечающем провайдере. Теперь `connect=10`, `read=180`, `write=30`, `pool=10`,
  а обмен на OAuth-токен получает собственные 15 секунд — ждать три минуты
  рукопожатия значит лишь откладывать ту же ошибку.
- Пул соединений создаётся с `pool_pre_ping=True` и `pool_recycle=1800`.
  Раньше `create_async_engine` вызывался без единого параметра пула, поэтому
  соединение, закрытое сервером по таймауту простоя или из-за рестарта,
  обнаруживалось запросом, который на нём падал: 500 на первом обращении после
  каждой паузы, по одному на каждое протухшее соединение, и само собой
  проходящее — что и делало его трудноуловимым.

### Fixed

- Джобы `lint` и `types` были красными: `ruff format --check` падал на 17
  файлах, `mypy` — на 34 ошибках. Красный гейт не проверяет ничего, поэтому
  оба падали на каждом push независимо от содержимого коммита.
- `PromptRequest` объявлял `topic: str` и `volume_pages: int`, тогда как
  `generate_document.py` строит его прямо из `Generation`, где оба поля
  `| None`. Это не гипотетическая нullability: гидратация из хранилища идёт
  через `Generation.__init__`, который не применяет ни проверку обязательного
  topic, ни проверку диапазона — то есть строка, записанная до появления этих
  проверок, доходит до `build_prompt` с пустым полем. Аннотации обещали
  гарантию, которой никто не давал; охранник `_reject_unrenderable_fields`
  существует именно потому, что значение действительно может отсутствовать.
- `ProjectItemDto.from_domain` передавал доменные `str` в поля с типами
  `ProjectKind` и `ProjectStatus`, полагаясь на приведение Pydantic. У двух
  enum'ов намеренно разная политика (`kind` считает неизвестное значение багом
  процесса, `status` деградирует в `unknown`), и приведение не показывало ни
  одной из них. Правило fail-closed вынесено в `_to_status`, который вызывают и
  `before`-валидатор, и `from_domain`.
- Оба дубля генерации перестали соответствовать своим портам, и тесты этого не
  замечали — usecase'ы обращаются к ним структурно.
  `FakeGenerationProvider.generate` всё ещё принимал сущность `Generation`
  после того, как сценарий 2.1 сузил порт до готовой строки, и писал её в поле,
  которое не читал ни один тест. У `FakeGenerationStorage` вовсе не было
  `find_by_owner_and_idempotency_key` и `count_retries_of`.
- Комментарий в `test_prompt_type_coverage.py` переносился так, что строка
  начиналась с `# type: `. mypy читал это как type-комментарий, сообщал о
  синтаксической ошибке и молча прекращал проверять остаток файла — модуля,
  который следит за тем, что у каждого поддерживаемого типа документа есть
  шаблон промпта.
- CAS-тесты хранилища сами определяли URL базы, по умолчанию указывая на
  `.../textery` — рабочую базу приложения, а не `textery_test`, — при том что их
  teardown делает `TRUNCATE` всех таблиц. Это ровно та ситуация, которая
  2026-08-06 стёрла данные локального стенда; защита, добавленная тогда, была
  единственным, мимо чего эти тесты проходили. Теперь они идут через неё.
- Два разных класса с именем `FakeGenerationStorage` (в `fake/generation/` и
  внутри `from_generation_statements`) с разными конструкторами и разными
  подмножествами порта. Встроенный удалён; тесты конверсии перешли на общий
  дубль, который воспроизводит CAS-конфликты и предикат владельца реального
  адаптера.

- Очистка тестовой БД (`TRUNCATE`) не включала таблицы `oauth_*`, из-за чего
  Postgres отклонял операцию целиком, строки утекали между тестами и полный
  прогон давал 8 падений и 45 ошибок.
- Набор `adapters/db` без поднятого Postgres зависал вместо понятного `skip`.
- Джоб `lint` в CI был красным: 21 замечание `ruff check` и 19 файлов без
  форматирования.
- Джоб `lint` покраснел повторно, вместе с `types`: 9 замечаний `ruff check`,
  10 неотформатированных файлов и 3 ошибки `mypy`. Общая причина у большинства
  из них одна — адаптер `adapters/rendering` приехал подключённым к `pythonpath`
  и `mypy_path`, но не к правилам качества: ни записи в `per-file-ignores` для
  сигнатур, заданных портом, ни стабов для его зависимости. Первый красный
  `lint` чинили как список замечаний, поэтому следующий новый модуль повторил
  ровно тот же путь.
- `types-Markdown` добавлен в `requirements.txt`. `ignore_missing_imports`
  этот случай не глушит и не должен: у пакета стабы на PyPI есть, и `mypy`
  сообщает, что их надо поставить, а не что типов не существует.
- `_load_completed_generation` возвращает текст генерации отдельным `str`, а не
  оставляет вызывающему читать `generation.content` типа `str | None`. Проверка
  на пустоту живёт внутри этого метода, а сужение терялось на границе — гарантия
  держалась на соглашении. Теперь до текста нельзя добраться в обход проверки,
  которая его доказывает.
- `container.__all__` не содержал `create_create_document_from_generation`,
  хотя `main.py` это имя импортирует. Пакет объявляет свой список реэкспорта
  контрактом — контракт был неполон, и `ruff` читал импорт как неиспользуемый.
- `test_document_router.py` импортировал `OWNER_ID` из `conftest`: на пути
  импорта этого набора лежат три `conftest.py`, поэтому константа могла
  привязаться не к той, что использует override клиента. Соседний conftest
  описывает эту ловушку прямо в docstring. Тест переведён на фикстуру `owner_id`.
- `FakeTokenService` не реализовывал `read_access_subject`: метод добавили в
  порт `TokenService` ради Bearer-зависимости, а дубль не обновили — он тихо
  перестал быть реализацией порта.

## [0.1.0]

Первый срез MVP: регистрация, вход, генерация документа через GigaChat и
ручной редактор. Всё под Clean Architecture — `domain → usecase → adapters →
application`, зависимости только внутрь.

### Added

- **Аутентификация по email.** Регистрация с кодом подтверждения, повторная
  отправка кода с кулдауном, подтверждение аккаунта, вход, обновление пары
  токенов. Пароли — bcrypt, токены — JWT HS256 с раздельными типами `access` и
  `refresh`.
- **Защита от перебора.** Счётчик подряд идущих неудачных входов, блокировка
  аккаунта на пороге, сброс счётчика при успешном входе. Инкремент атомарен на
  стороне БД.
- **Вход через Яндекс OAuth.** Legs `start` / `callback` / `exchange`, привязка
  CSRF-state, одноразовый handoff-код вместо токена в редиректе,
  общий на все реплики rate-limit по (leg, источник).
- **Генерация документов.** Постановка задачи, фоновое исполнение с
  экспоненциальным backoff и джиттером, периодический sweep зависших генераций
  после перезапуска процесса.
- **Ручной режим.** Создание документа, идемпотентное по `Idempotency-Key`,
  чтение, сохранение с оптимистичной блокировкой по `version` (single-statement
  compare-and-swap), санитизация HTML через nh3.
- **История с keyset-пагинацией** для генераций и документов — курсор по
  неизменяемой паре `(created_at, id)`.
- **Единый конверт ошибок** `{error_code, message}` для всех ответов, включая
  404 и 500; внутренние детали уходят только в лог.

### Security

- Все данные привязаны к владельцу, предикат `owner_id` — в SQL. Чужой ресурс
  отвечает `404`, а не `403`: `403` подтвердил бы, что он существует.
- `JWT_SECRET` без значения по умолчанию и с проверкой длины ≥32 байт
  (RFC 7518 §3.2) на старте; `DATABASE_URL` — именованная ошибка конфигурации.
- Вход не различает «нет такого аккаунта» и «неверный пароль»; проверка
  `is_verified` идёт после проверки пароля, чтобы ответ не работал оракулом
  существования аккаунта.

### Known limitations

- Refresh-токены stateless, списка отзыва нет: утёкший refresh-токен работает
  до истечения срока.
- Очередь генераций (`NoOpGenerationQueue`) не переживает перезапуск процесса;
  восстановление держится на sweep с интервалом 60 с.
