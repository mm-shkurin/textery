## Правила, выведенные болью прошлой сессии

Прочитай их прежде чем начинать — каждое стоило переделки.

1. **Не гоняйся за счётчиком проб.** `SMELL-LONG-FUNC` для TSX — эвристика по фигурным
   скобкам: любая правка перетасовывает, какие блоки она видит, и «починка» одного
   выпускает наружу два новых. Для Python она считает строки **вместе с докстрингами**.
   Улучшай код по существу; проба — индикатор, не цель.
2. **Проверяй, что комментарий не врёт.** В прошлый проход три свежих комментария
   утверждали гарантии, которых код не давал, и один README-инвариант был сломан тем же
   коммитом, который его написал. Если пишешь «это гарантирует X» — открой код и убедись.
3. **Правка текста может замаскировать баг.** Быстрый старт фронта не работал из-за
   `vite.config.ts`, а не из-за README; правка README сделала проблему невидимой.
   Если чинишь документацию про запуск — **воспроизведи запуск**.
4. **Не добавляй waiver сам.** `probes/waivers.json` — решение человека. Восемь уже
   есть, все истекают 2026-10-01.
5. Полная сюита фронта идёт ~3 минуты и иногда даёт флейк на ленивом чанке `DocArea`
   (`ChatWorkspace.test.tsx`). Если упал один такой тест — прогони изолированно, прежде
   чем считать это регрессией.
6. Тесты `backend/adapters/db` требуют живой Postgres. Без него гоняй
   `python -m pytest -q domain usecase adapters/rest adapters/security adapters/oauth_provider adapters/geolocation_provider application`

## Приоритет 1 — безопасность и продакшн-поведение

Каждый пункт меняет рантайм, поэтому прошлая сессия их не трогала. Здесь они —
основная работа. Перед каждым: `/architecture` или хотя бы явное решение в коммите.

### 1.1 Нет ограничения по IP на `/login`, `/register`, `/resend-code`
Есть только блокировка по аккаунту после N неудач. Значит credential stuffing,
размазанный по многим аккаунтам с одного источника, ничем не ограничен на уровне
приложения. Ограничитель уже существует и работает в БД для OAuth-ног:
`backend/usecase/src/auth/oauth/rate_limiter.py`,
`backend/adapters/db/src/access/auth/oauth_rate_limit_storage.py`,
проводка в `container/oauth_wiring.py`. `container/auth_wiring.py` его не использует
(проверено: `grep -n "rate_limiter\|rate_guard" auth_wiring.py` пуст).
**Задача:** подключить тот же ограничитель к трём парольным маршрутам.
**Осторожно:** субъект бакета не должен быть сырым IP в логах — в аналитике для этого
берётся усечённый SHA-256 (`analytics_router.py`, функция `_source_of`), сделай так же.
**Приёмка:** тест, что N+1 попытка с одного источника по разным аккаунтам получает 429.

### 1.2 Нет CORS вообще
`grep -rn "CORSMiddleware\|allow_origins" backend/application/src backend/adapters/rest/src`
даёт ноль. Работает только потому, что nginx стоит перед `/api/`. Но `backend/` публикуется
как самостоятельный репозиторий со **своим** `docker-compose.yml`, который публикует порт
бэкенда напрямую — там браузерный клиент упрётся в непонятную ошибку.
**Задача:** список разрешённых origin из переменной окружения, без рабочего значения по
умолчанию (тот же принцип, что у `VITE_API_PROXY_TARGET`), плюс тест на политику.

### 1.3 `UnlimitedSearchSlots` — заглушка на публичном маршруте
`backend/application/src/app/container/project_wiring.py:12`. Порт `SearchSlots` обязателен
в конструкторе `ListProjects`, но реализация возвращает `True` безусловно, а `release()`
пуст. То есть неиндексированный поиск по содержимому в ленте проектов не ограничен по
параллелизму вообще. Докстринг про это честен — но это не оправдание.
**Задача:** либо настоящая реализация со счётчиком в БД, либо убрать порт и записать
почему. Второе — тоже валидный ответ, если ограничение сейчас не нужно.

### 1.4 Развёртка стирает генерации параллельно во всех репликах
`backend/application/src/app/main.py:56` — `_sweep_loop()` крутится в каждом процессе
с интервалом 60 с. Бэкенд по правилам проекта работает в нескольких экземплярах
(`.claude/rules/coding-rules.md`), и от дублей спасает только CAS на стороне БД в
`usecase/src/generation/requeue_stale_generations.py`. Гарантия нигде не записана рядом с
местом, где она нужна.
**Минимум:** зафиксировать её в докстринге у `_sweep_loop`, со ссылкой на CAS.
**Лучше:** advisory lock или единственный бегун.

## Приоритет 3 — долг, названный аудиторами

### 3.1 `conftest.py` целиком исключён из mypy
`backend/pyproject.toml:180` — `exclude = ['(^|/)conftest\.py$']`, потому что шесть
слоёв дают шесть модулей с именем `conftest` и mypy отказывается. Обходной путь
задокументирован, но весь общий фикстурный код не проверяется типами.
**Задача:** дать каждому уникальное имя модуля и реэкспортировать, вернув проверку.

### 3.2 12 тестов за `pytest.importorskip`
В основном `adapters/rendering` — гейтятся на нативные библиотеки WeasyPrint/docx.
CI их ставит, но локальный прогон без них показывает зелёное при полностью
невыполненном пути экспорта.
**Задача:** флаг окружения, который в CI превращает пропуск в ошибку.

### 3.3 `DocumentCreation` — недовведённая абстракция
`backend/usecase/src/document/document_creation.py`. Проверяющий прошлой сессии назвал
это точно: оба usecase **всё ещё** держат репозиторий и unit of work своими полями и
используют их напрямую в recovery, так что коллаборатор — третья ссылка на те же два
объекта. Хуже: `CreateDocument.execute` больше не показывает, где коммитится его
транзакция — она уехала в хелпер.
**Задача:** либо довести (recovery тоже через коллаборатор, поля убрать), либо откатить
до простой функции и принять, что вызов повторяется. Спрятанная граница транзакции —
это то, чего извлечение делать не должно было.

### 3.4 Объём комментариев

## Что НЕ делать

- Не публиковать в GitVerse без явной команды владельца. Это необратимо и наружу.
- Не трогать `*/docs/testing/**` — чужая зона (см. выше). Там есть известные расхождения
  (`frontend/docs/testing/README.md` говорит «десяти историй» при одиннадцати папках;
  таблица покрытия в `backend/docs/testing/README.md` не сходится с файлами) — **сообщи
  владельцу, не чини**.
- Не переписывать опубликованную историю ради проб.
- Не ослаблять линтеры, пороги покрытия и не добавлять blanket-ignore.
