# Scenario 3.2 — An export error is shown with retry, document unchanged

## green-selenium (2026-07-27)

**Quirk:** Selenium `element.text` on a `data-testid` node returns the whole subtree's text, so an interactive child (the retry `<button>`) nested inside the `export-error` message node concatenated "Повторить" into the exact-text acceptance pin and failed it — while the unit-level `toHaveTextContent` matched substrings and never caught it.
**Where:** ExportControl error banner (`ExportControl.tsx`); acceptance `manual_editor_export_error_statements.py` exact-text assertion.
**Implication:** Keep any testid node an acceptance pins by exact text free of text-bearing children — put the retry as a sibling in a wrapper; at unit level assert whole-node text with `.toBe(el.textContent?.trim())`, not `toHaveTextContent`.
