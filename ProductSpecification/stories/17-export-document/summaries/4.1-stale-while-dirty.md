# Scenario 4.1 — Exporting with unsaved edits saves or warns first

## red-selenium (2026-07-27)

**Decision:** On export with unsaved edits, save first (PUT /documents/{id}) then fire the export GET — chose the spec's save-first branch over an explicit warn dialog.
**Why:** Export renders the *stored* HTML, so unsaved edits would ship a stale file; save-first reuses the existing `useDocumentSave`/`save()` machinery and adds no new modal UI, and is the lower-risk flow.
**Where applied:** `ExportControl` — green threads `hasUnsavedChanges` + `save` in from `ManualEditor.tsx:164` (today ExportControl receives only `documentId`).
