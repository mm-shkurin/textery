# Scenario 1.1: Selecting a type goes straight to generation — Journey Summary

## green-frontend (2026-07-28)

**Decision:** Selenium contract testid `generation-generating` is delivered by adding a `data-testid='generation-generating'` element on `DocArea`'s **pending** branch, not by repointing the Selenium locator to an existing testid.
**Why:** Keeps the red-selenium contract intact; the pending surface is also scenario 1.2's subject, so one testid serves both.
**Where applied:** `frontend/src/features/generation/components/DocArea.tsx`.

## green-frontend (2026-07-28)

**Surprise:** `selectType('doklad')` sets `step='form'`+`mode='auto'` but does NOT start a generation — `ChatWorkspace` renders the idle composer, so the `generation-generating` pending surface is unreachable on load.
**Why:** `createGeneration` needs a real topic and there is no topic source until the composer is used; an empty-topic auto-POST would be rejected by the backend.
**Impact:** green-selenium 1.1 stays blocked (must not remove the skip marker) until auto-start + a deterministic pending window land in red-frontend-api/align-design.

## green-frontend (2026-07-28)

**Quirk:** Removing the mode-select modal made the blank/non-AI `ManualEditor` create path unreachable — `mode==='manual' && openDocumentId===null` is now dead (only `openDocumentFromHistory` sets manual, always with an id).
**Where:** `frontend/src/app/useFlowNavigation.ts`, `DocumentGenerationFlow.tsx:67`.
**Implication:** Story 5's non-AI create is intentionally down until scenario 6.1 restores "blank document from scratch"; 6.1 must add a reachability guard, else it ships as a silent regression.

## green-frontend (2026-07-28)

**Quirk:** Deleting the mode modal broke Story 5's `test_mode_modal_acceptance.py` (waited on the removed `[data-testid='mode-modal']`); it was marked `@pytest.mark.skip` OBSOLETE.
**Where:** `acceptance/tests/frontend/generation/test_mode_modal_acceptance.py`; `ModeModalStatements` fixture (conftest) + `MODE_CARD_AUTO` in `base_frontend_statements.py` are now unused.
**Implication:** A later cleanup should retire the dead statements/fixture/locator; frontend acceptance runs must account for the skip.
