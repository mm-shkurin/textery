# Scenario 2.1: A completed generation opens automatically in the editor

## red-frontend-api (2026-07-30)

**Mistake:** Verified a rewritten assertion by biting it with a `perl -0pi` substitution on the `Idempotency-Key` header line.
**Why wrong:** `documentApi.ts` has two structurally identical call sites, so the regex matched the first one — inside `createDocument` — and damaged an unrelated working function while the suite stayed green, which read as "the bite did not land".
**Correct location/approach:** Bite a specific call site by editing it directly, never by a regex that can match a sibling.

## green-frontend-api (2026-07-30)

**Quirk:** `send.ts` flattens transport error types — a `RequestTimeoutError` becomes a plain `Error`, and `describeFailure` returns `error.message` in preference to the caller's fallback, so a caller-supplied Russian message is unreachable on the timeout path.
**Where:** `frontend/src/shared/api/send.ts`, `frontend/src/shared/api/httpClient.ts`.
**Implication:** Any caller needing to distinguish a retryable failure (or to guarantee its own message) must bypass `send` as `OAuthCallback` does, or preserve the type explicitly.

**Quirk:** The editor cannot hold markdown — `useManualEditorInstance` configures `Document.extend({ content: 'inline*' })`, and Tiptap's HTML parser deletes any `<` followed by a letter, so `'Формула: <i и <j'` silently loses text.
**Where:** `frontend/src/features/generation/components/useManualEditorInstance.ts`.
**Implication:** Whatever opens the editor must feed it the server-sanitized HTML from the conversion response, never the generation's markdown body.
